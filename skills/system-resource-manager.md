# SYSTEM RESOURCE MANAGER: OPERATIONAL LIMITS AND PERFORMANCE TUNING

Этот документ регламентирует правила расходования системных ресурсов (память, процессорное время, дисковый ввод-вывод) при выполнении тяжелых бинарных и RAG-задач на локальном сервере.

---

## ПРЕДПОЛЕТНЫЕ ПРОВЕРКИ РЕСУРСОВ (PRE-FLIGHT CHECKS)

Перед запуском ресурсоемких задач (таких как векторизация базы RAG, декомпиляция бинарных файлов большого объема, компиляция тяжелых C++ библиотек) агент обязан проверить текущее состояние Windows-системы:

1. **Дисковое пространство**:
   - Минимально необходимый свободный объем на активном разделе: 2 GB.
   - Проверка осуществляется через PowerShell: `Get-PSDrive -PSProvider FileSystem`.
2. **Оперативная память (RAM)**:
   - Минимально свободный объем RAM для компиляции или ML-инференса: 1 GB.
   - Проверка осуществляется через PowerShell: `Get-CimInstance Win32_OperatingSystem`.
3. **Состояние GPU**:
   - Для Intel Arc проверяйте доступность PyTorch XPU через `torch.xpu.is_available()`; для NVIDIA используйте `nvidia-smi` и `torch.cuda.is_available()`.

---

## ПРИОРИТИЗАЦИЯ И ПЛАНИРОВАНИЕ ПРОЦЕССОВ (NICE/IONICE)

Все тяжелые фоновые вычисления, способные вызвать зависание пользовательского интерфейса, должны запускаться с пониженным приоритетом планировщика:

1. **Приоритет CPU (niceness)**:
   - Для фоновых задач на Windows запускайте процесс с пониженным приоритетом через `Start-Process -Priority BelowNormal`.
   - Пример: `Start-Process .\rag-venv\Scripts\python.exe -ArgumentList '.\scripts\rag_engine.py index-code .\scripts' -Priority BelowNormal -Wait`.
2. **Приоритет дискового ввода-вывода**:
   - Windows не предоставляет прямой аналог `ionice` в стандартной PowerShell-среде; ограничивайте тяжелые задачи расписанием и размером батчей.

---

## ОПТИМИЗАЦИЯ РАБОТЫ С ПАМЯТЬЮ И ВРЕМЕННЫМИ ДИСКАМИ

1. **Временные файлы**:
   - Для временных файлов RAG используйте `$env:TEMP` или отдельный каталог внутри проекта. Не используйте Linux-only пути.
2. **Ограничение VRAM и использование GPU**:
   - Основной путь для Intel RAG: локальная модель SentenceTransformers через PyTorch XPU (`torch.xpu`). NVIDIA CUDA остаётся отдельным поддерживаемым backend.
   - Запрещено выполнять математические вычисления RAG-моделей на CPU.
   - `RAG_STRICT_GPU=1` является обязательным режимом для этого проекта.

---

## БАЗЫ ДАННЫХ И СОЕДИНЕНИЯ (POSTGRESQL POOL LIMITS)

1. **Connection Pooling**:
   - Запрещено создавать новые соединения к базе данных на каждый HTTP-запрос или при каждой RAG-операции.
   - Используйте встроенные пулы соединений (`psycopg_pool` для Python) с ограничением `max_size=10`.
2. **Таймауты БД**:
   - Устанавливайте жесткий таймаут выполнения запросов: `statement_timeout = 30000` (30 секунд) для предотвращения зависания транзакций и утечек соединений.

---

## ГИГИЕНА И АВТОМАТИЧЕСКАЯ ОЧИСТКА ВРЕМЕННЫХ ФАЙЛОВ

1. **Ротация логов (Log Rotation)**:
   - Размер файла логов `rag_engine.log` или `app.log` не должен превышать 50 MB.
   - Применяйте автоматическую ротацию (например, `RotatingFileHandler` в Python с `backupCount=3`).
2. **Очистка временных папок**:
   - Для PowerShell-скриптов создавайте временные каталоги через `New-Item -ItemType Directory` внутри `$env:TEMP` и удаляйте их в `finally`.
   - Не оставляйте «мусорных» файлов сборки в рабочих директориях.

---

## ПРАВИЛА ВЫПОЛНЕНИЯ ПРИВИЛЕГИРОВАННЫХ КОМАНД (SUDO)

1. **Категорический запрет на несанкционированный запуск sudo**:
   - Агенту строго запрещено генерировать или пытаться выполнять команды с `sudo` напрямую в автоматическом режиме. Это приводит к блокировке или отказу со стороны системы безопасности.
   - Если операция требует повышенных прав (например, настройка `chattr` или запуск Docker-контейнеров на системных портах), агент обязан сгенерировать точную команду и вежливо попросить пользователя выполнить ее вручную.
